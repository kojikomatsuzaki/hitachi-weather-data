# 観測史を反映する検索UI — 設計草案 v0.1

## 目的
1953年以降の観測記録について、観測頻度・観測時刻・観測要素・原資料の記載方法の変遷を隠さず、利用者が存在しないデータを探さない検索画面を提供する。

## 検索の入口
1. 年月日から探す（一般利用者向け・既存画面の後継）
2. 観測項目から探す（収録期間と比較可能性を確認）
3. 観測史から探す（時刻・頻度・資料形式の変遷）

## 検索用インデックス
正本YAMLと採録方針Markdownから生成する派生JSON。年単位で決め打ちせず、観測所・年月日・項目単位で利用可能な観測時刻と集計値を記録する。毎時、3時間ごと、日中のみ、1日数回、1日1回などの頻度はデータから導出し、原資料の時刻表記を保持する。

## 状態の区別
- 観測値あり
- 原資料に「欠測」と明記
- 原資料のセルが空欄
- 原資料に「-」などの記号
- 当該時刻の観測記録なし
- 当該項目が資料に存在しない
- 原資料は存在するが未採録
- 原資料自体が未確認

これらを単一の null や 0 に統合しない。観測時刻と日別集計は別扱いとする。

## UIの原則
- その日・その項目に実在する観測時刻のみ選択候補として表示する。
- 時刻のスライダーを固定1〜24時とする設計は再検討する。
- 観測項目は利用可否を表示し、非対応の理由を説明する。
- 観測史の年表は実際の原資料・メタデータに基づき、推測した境界年を掲載しない。
- 年代をまたぐ比較では観測回数・時刻・単位・測定方法の相違を明示する。
- スマートフォン・キーボード・スクリーンリーダーで操作できること。

## 移行と検証
既存の docs/index.html と app.js は維持し、試作画面を別経路で作成する。1953年、1970年代、1990年代、2025年の原資料・生成データを照合し、観測項目と時刻の実在性を確認してから切り替える。正本YAMLはUI都合で変更しない。
